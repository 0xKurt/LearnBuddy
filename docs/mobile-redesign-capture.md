## Requested work and durable lifetime

Per-key Chat draft subscriptions prevent a hidden editor from restoring stale text. Upload submission binds its immutable caption, account and client ID in the existing draft store before asynchronous persistence; Chat cannot separately submit that same requested caption, including when Capture starts during a recovery lookup. Unrelated newer text remains sendable. Durable Chat text is cleared only after the submitted Capture draft is saved. Empty/duplicate sends reserve nothing; failure retains or restores only an empty matching-account draft.

Confirmed uploads persist the existing sent-material record with caption identity before clearing the matching photo draft. Read/modify/write operations share the store's existing serialization. Restart recovery checks the actual Home thread before an explicit retry, retains the same client ID when confirmation is unavailable, and never blindly resends. Actual server confirmation returns a typed confirmed outcome, clears only the matching recovered draft and prevents an already-captured click from using a fresh ID. A later deliberate same-text intent is independent. Explicit edits supersede recovered text; pre-existing newer text is preserved.

Submission completion, original-material invalidation and silent caption delivery can outlive the page. Navigation, page errors and other local completion remain focus/lifetime guarded. Storage generation, captured account and actual Query identity prevent late sends, cache writes or draft restoration after wipe/replacement, including returning to the same account. The guard is checked again after sent-record persistence. No hidden-route reply is spoken.
